# الصفحة الموحدة للشروط والأحكام وسياسات الاستخدام — https://baranda.shop/terms

## الفكرة
- صفحة واحدة بخمسة أقسام (شروط الاستخدام / الخصوصية والأمان / البيع والرسوم / نشر الصور والفيديو / حقوق النشر) بدل خمس موافقات منفصلة.
- فى التطبيق (إنشاء حساب بالبريد + إكمال بيانات حساب جوجل): **مربع اختيار واحد** بنص
  «بالضغط على إنشاء حساب، فإنك توافق على **الشروط والأحكام وسياسات الاستخدام** الخاصة بالتطبيق.» والعبارة الملوّنة رابط يفتح الصفحة.
- الموافقة تُسجَّل كما كانت (وقتها + `POLICIES_VERSION`) فى `profiles.policies_accepted_at / policies_version`.

## مصدر النصوص (واحد فقط)
`data/policies.ts` هو المصدر الوحيد: التطبيق (`app/policy/[key].tsx`) والصفحة على الدومين يقرآن منه.
أى تعديل على النصوص: عدّل الملف ← غيّر `POLICIES_VERSION` ← أعد توليد الصفحة ← انشر الويب.

## التوليد والنشر
```bash
npm run build:terms   # يكتب public/terms/index.html من data/policies.ts
npm run build:web     # يولّد الصفحة ثم expo export --platform web (مجلد public/ يُنسخ لجذر dist)
```
انشر محتوى `dist/` على الدومين **baranda.shop**. المسار `/terms` يقدّم `terms/index.html` تلقائيًا على Netlify / Vercel / Cloudflare Pages / Firebase Hosting
(الملفات الموجودة لها أولوية على قاعدة الـ SPA fallback `/* → /index.html`). تحقّق بعد النشر: افتح https://baranda.shop/terms (يجب أن تظهر الأقسام الخمسة، لا شاشة التطبيق).
لو الاستضافة عندك تعيد توجيه كل المسارات لـ `index.html` حتى الموجودة، أضف استثناء للمسار `/terms`.

## السلوك على كل منصة (lib/terms.ts)
- الويب: تبويب جديد. أندرويد/آيفون/APK: متصفح داخل التطبيق ثم الرجوع لنفس الشاشة. لو فشل الفتح (لا إنترنت) يُعرض نص الشروط المضمّن داخل التطبيق.
- لا يحتاج الأمر build native جديد للرابط نفسه، لكن التعديل داخل التطبيق يحتاج build/OTA جديد.
