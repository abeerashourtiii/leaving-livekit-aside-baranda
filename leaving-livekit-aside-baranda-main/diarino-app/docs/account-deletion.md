# حذف الحساب من داخل التطبيق

**المسار:** الإعدادات ← بطاقة حسابك ← «تعديل بيانات الحساب» ← أسفل الصفحة «حذف حسابي» (خطوتا تأكيد). (انتقل من الإعدادات — لم يعد هناك زر حذف أسفل «تسجيل خروج»، ولا يظهر أثناء الإكمال الإجبارى بعد جوجل). للمسجَّلين فقط (لا يظهر للضيف). يعمل على أندرويد وآيفون والويب وAPK.

## ماذا يحدث
- `supabase.rpc("delete_my_account")` (migration `20261015000000_account_deletion_and_live_rights.sql`) يحذف المستخدم من `auth.users`.
  الحذف ينتشر (cascade) إلى: الملف الشخصى، الإعلانات، التعليقات والإعجابات، المفضلة، المحادثات، الإشعارات، رموز الإشعارات، الأدوار...
  (فُحص كامل رسم العلاقات: 40 مفتاحًا أجنبيًا يشير للمستخدم/الملف الشخصى، كلها cascade أو set null).
- بعدها يُمسح الجلسة المحلية والكاش (`signOut`) ويُحوَّل المستخدم للرئيسية.

## متى يُرفض
| الخطأ | السبب | ما يراه المستخدم |
|---|---|---|
| `has_open_fees` | عليه صفقة بحالة reported / invoiced / disputed | «لا يمكن حذف الحساب لوجود رسوم مستحقة…» |
| `super_admin_cannot_delete` | هو المشرف الأعلى الوحيد | «انقل الصلاحية أولًا» |
| `not_authenticated` | ضيف / غير مسجَّل | لا يظهر الزر أصلًا |

## ما يبقى بعد الحذف (عن قصد)
- **سجل الصفقات والرسوم** `property_deals`: يبقى مع نسخة من الاسم/الهاتف/البريد وقت الإبلاغ (`payer_name/phone/email`) و`payer_id = null`،
  لأغراض المحاسبة والنزاعات. ذُكر ذلك فى سياسة الخصوصية والشروط.
- **ملفات Cloudinary** (صور/فيديو/موسيقى المحذوف حسابه): تبقى على Cloudinary لأن حذفها يتطلب مفتاح API سرى.
  لا يوجد فى قاعدة البيانات أى سجل يشير إليها بعد الحذف. للتنظيف: Edge Function تستدعى Cloudinary Admin API (غير منفَّذة).

## سجل التدقيق
حذفات الـ cascade الناتجة عن حذف الحساب لا تُسجَّل فى `admin_audit_log` (ليست إجراءً إداريًا)، وتم إصلاح `log_admin_change`
لأنه كان يمنع الحذف بخطأ FK (اكتُشف فى الاختبار على PostgreSQL).

## متطلبات المتاجر
- Apple 5.1.1(v): حذف الحساب داخل التطبيق ✔ (أضف رابط السياسة فى App Store Connect).
- Google Play: «حذف الحساب» داخل التطبيق ✔ + رابط ويب لطلب الحذف فى Data safety: استخدم `https://baranda.shop/policy/privacy` (يشرح المسار).

## حذف حساب المشرف (أدمن) — بموافقة السوبر أدمن فقط (migration `20261026000000_admin_account_deletion_approval.sql`)
- أى مشرف يضغط «حذف حسابي» لا يُحذف حسابه: `delete_my_account()` ترفض بـ `admin_requires_super_admin_approval`، فيرسل التطبيق تلقائيًا
  طلبًا عبر `request_admin_account_deletion()` (جدول `account_deletion_requests`) ويظهر له «طلب الحذف قيد المراجعة» مع زر «سحب طلب الحذف».
- السوبر أدمن يرى الطلبات فى لوحة التحكم ← المشرفون (أعلى الصفحة) ويضغط «موافقة» (`admin_approve_account_deletion` — يحذف الحساب فعليًا بعد
  إعادة فحص الرسوم المستحقة ويسجّل القرار فى `admin_audit_log`) أو «رفض» (`admin_reject_account_deletion`).
- حساب السوبر أدمن نفسه لا يُحذف قبل نقل الصلاحية (`super_admin_cannot_delete`). الحماية على مستوى قاعدة البيانات فلا يمكن تجاوزها بالتطبيق.
- بعد الموافقة يبقى سجل الطلب (اسم/بريد المشرف ووقت القرار) للتدقيق مع `user_id = null`.
